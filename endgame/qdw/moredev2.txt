The repo is at a good point to start implementation precisely because there is almost no legacy code to fight. On GitHub, `StallSpy` still has a single initial commit on `master`; the repository is the research/product specification rather than a functioning application.  The existing blueprint already identifies the Etsy gateway, listing compiler, policy engine, market signals, audit trail and experiment concepts, while the template and Trend Radar docs give concrete domain formats rather than vague product prose.

The pasted MD adds the missing second layer: **StallSpy stops being merely an Etsy app and becomes the commerce-world implementation feeding private-lab/mwgym-style economic experiments.** In particular, `available_at`, historical replay, MarketWorlds, structured decisions and future reveals are the right abstractions. 

One correction to the MD before implementation: UCI Online Retail II contains 1,067,371 real transaction rows and is CC BY 4.0, but it does **not** contain procurement cost or historical inventory-on-hand. So the first benchmark can truthfully evaluate demand selection, forecasting and revenue capture; it cannot claim historical realized P&L unless we explicitly add a synthetic cost model. ([UCI Machine Learning Repository][1])

Give the coding agent this:

# 3. Define the temporal provenance model first

This is the most important code in the project.

Create:

```text
src/stallspy/contracts/temporal.py
```

Models:

```python
TemporalProvenance
SourceArtifact
ObservationRef
```

Every source datum capable of entering a historical world must ultimately expose:

```text
event_time
observed_at
published_at
available_at
ingested_at
source_id
source_type
license
content_digest
artifact_ref
```

Semantics:

```text
event_time
when the underlying real-world event happened

observed_at
when the original observer/provider observed it

published_at
when it was published externally

available_at
earliest moment our historical operator is allowed to know it

ingested_at
when StallSpy actually acquired it
```

The fundamental benchmark rule is:

```python
assert observation.available_at <= world.world_time
```

for every observation provided to the operator.

Never infer availability merely from `event_time`.

Example:

```text
Consumer purchase:
event_time     = 2024-11-25

Report describing purchase:
published_at   = 2025-01-10

World:
2024-12-01

result:
REPORT MUST NOT BE VISIBLE
```

Implement `LeakageGuard`.

Any world materialization containing unavailable evidence must fail hard.

Everything after that—eBay historical research, eBay Sandbox, Etsy live experiments, Oracle calibration, Arenav2 tournaments, Operator Twin and Moltwork policy learning—has a proper substrate instead of being another pile of agent code.

The most important engineering distinction is **historical prediction vs real economic P&L**. eBay Product Research genuinely gives three years of sold-market data, making it excellent for replay and market forecasting. ([eBay][2]) But historical sold data still doesn't tell us what *our* sourcing cost would have been. True P&L starts once StallSpy records actual inventory acquisition cost, marketplace fees, shipping, refunds and sales from its own live operation.

That actually makes the progression cleaner:
